# Vera Practice

Голосовой тренажёр коммуникации врача с недовольным пациентом. Врач (студент-медик,
ординатор) выбирает сценарий, разговаривает с «живым» анимированным пациентом
голосом или текстом и получает разбор по критериям признанных стандартов —
NURSE, Calgary–Cambridge Guide и принципов Beauchamp & Childress.

Работает локально: один Next.js-сервер, все вызовы AI (генерация сцены, озвучка,
распознавание речи, оценка) идут на стороне сервера через OpenAI-совместимый
провайдер. Ключ живёт только в `.env`, в браузер не попадает.

---

## Возможности

**Сценарии**
- Пять разделов приёма: амбулатория, терапия, хирургия, педиатрия, стационар — 20+ категорий жалоб.
- Сценарии собираются процедурно из осей: повод жалобы, эмоциональный профиль, скрытый мотив, персона пациента. История комбинаций отслеживается, и сводка «что уже было» уходит генератору — чтобы сцены не повторялись и не скатывались в клише.
- Полноценный диалог: открывающая жалоба + 3–4 ответа врача, пациент реагирует на каждую реплику («живой актёр»), его эмоция меняется по ходу разговора.

**Пациент**
- 2.5D-персонаж в векторном SVG-риге: восемь персонажей с разной внешностью, мимика управляется эмоциями (раздражение, злость, агрессия, слёзы, сарказм, холодная вежливость, тревога, печаль), дыхание, моргание, движения глаз, слёзы.
- Синхронизация губ с озвучкой: русская орфография → виземы, длительности реплик выравниваются по реальному аудио через WebAudio-анализатор; текущее слово подсвечивается в субтитрах.
- Озвучка — нейроголос провайдера с дисковым кэшем (одна и та же реплика синтезируется один раз).

**Диалог и ввод**
- Ответ голосом (запись с микрофона + распознавание речи) с индикатором громкости и лимитом времени — или текстом, как запасной вариант.
- Реплику пациента можно повторить; субтитры-«караоке» с подсветкой слова.

**Оценка и история**
- Разбор «супервизора» по 5 критериям (4 универсальных + 1 по поводу жалобы), каждый на шкале 0–2/0–3, с дословными цитатами-доказательствами и прямыми объяснениями.
- Критерии опираются на признанные стандарты — полная привязка в [EVALUATION_STANDARDS.md](EVALUATION_STANDARDS.md).
- Отдельные сигналы: `safety_flag` (клинически небезопасный совет) и `flags` (попытки prompt injection в ответе).
- История прогонов со счётом, экран результатов с вердиктом и «пройти похожую сцену».

## Стек

- Next.js 15 (App Router) + React 19 + TypeScript (strict), единый сервер
- SQLite через better-sqlite3 (WAL); TTS-кэш и загруженное аудио на диске
- Анимация лица — прямые DOM-мутации в rAF (без ре-рендеров React на кадр)
- AI: единый внутренний слой `AiProvider` (chat / tts / stt) — OpenAI-совместимый
  провайдер через HTTP, всё на сервере

Node.js ≥ 20 (проверено на Node 22, Windows 10/11).

## Запуск

**Windows: двойной клик по `start.cmd` в корне проекта.** Готовить ничего не
нужно. Скрипт сам:

1. проверит Node.js — если в системе нет версии 20+ или она устарела, скачает
   портативную сборку прямо в папку проекта (`.node`, ~30 МБ, с проверкой
   контрольной суммы) и будет использовать её;
2. при первом запуске поставит зависимости (`npm install`);
3. поднимет сервер и откроет браузер, когда тот будет готов.

Права администратора и установка в систему не нужны — система не меняется,
скачанный Node удаляется вместе с папкой `.node`. Если Node.js 20+ уже стоит,
используется он и ничего не качается. Интернет нужен только при первом запуске.

Открывшееся консольное окно закрывать нельзя: пока оно открыто, тренажёр
работает. Остановить — `Ctrl+C` или закрыть окно.

### Ключ доступа

Ключ вводится в самом приложении. При первом запуске вместо тренажёра откроется
экран «Подключите AI-провайдера»: вставьте ключ, он проверится у провайдера и
сохранится на этом компьютере в `data/settings.json` (папка в `.gitignore`).

Ключ не уходит в браузер: все обращения к AI идут через сервер проекта, а наружу
отдаётся только маска вида `sk-…fz0r`. Поменять ключ или подключить другого
OpenAI-совместимого провайдера можно в любой момент — кнопка «Подключение» в шапке.

Привычнее файлом — скопируйте `.env.example` в `.env` и заполните `AI_API_KEY`.
Приоритет источников: `data/settings.json` → `.env.local` → `.env` → переменные
окружения процесса.

### Вручную (Linux/macOS, CI)

```bash
npm install

cp .env.example .env             # необязательно: ключ можно ввести через интерфейс
# заполните AI_API_KEY в .env (файл в .gitignore — не коммитится)

npm run dev                      # разработка: http://localhost:3000
npm run build && npm run start   # production-сборка и запуск
```

Оживить браузер, когда сервер уже поднялся (используется в `start.cmd`):

```bash
node scripts/open-when-ready.mjs            # открыть http://localhost:3000
node scripts/open-when-ready.mjs --print    # только дождаться готовности
```

Переменные окружения (`config` в `lib/config.ts`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AI_BASE_URL` | `https://api.proxyapi.ru/openai/v1` | OpenAI-совместимый endpoint |
| `AI_API_KEY` | — | ключ провайдера (обязателен) |
| `AI_CHAT_MODEL` | `gpt-4o-mini` | генератор сцен и «актёр»-пациент |
| `AI_EVAL_MODEL` | `gpt-4o-mini` | AI-оценщик (детерминированный temperature 0; компромисс цена/качество) |
| `AI_TTS_MODEL` | `gpt-4o-mini-tts` | озвучка пациента |
| `AI_STT_MODEL` | `gpt-4o-mini-transcribe` | распознавание речи врача |
| `PORT` | `3000` | HTTP-порт |
| `DIALOG_EXCHANGES` | `3` | обменов «ответ врача → реплика пациента» (1–4) |
| `RECORD_MAX_SECONDS` | `60` | лимит записи голоса |
| `DATA_DIR` | `data` | БД, кэш озвучки, загруженное аудио и `settings.json` с ключом из интерфейса |

Проверенные на указанном провайдере модели перечислены выше; при смене
провайдера поменяйте адрес в «Подключении» (или модели в `.env`) и прогоните
`npm run probe`.

## Скрипты

| Команда | Что делает |
|---|---|
| `start.cmd` | Windows: запуск двойным кликом — проверка Node, установка зависимостей, сервер, браузер |
| `npm run dev` | сервер разработки |
| `npm run build` | production-сборка |
| `npm run start` | запуск production-сборки |
| `npm run typecheck` | строгая проверка типов (`tsc --noEmit`) |
| `npm run probe` | проверка доступности провайдера и моделей (chat/tts/stt) |
| `npm run regression` | регресс AI-оценщика: 18 эталонных диалогов, сверка диапазонов баллов |
| `node scripts/e2e-smoke.mjs` | сквозной смоук против запущенного сервера (сцена → TTS → диалог → оценка → история) |
| `node scripts/open-when-ready.mjs` | дождаться ответа сервера и открыть браузер (`--print` — только дождаться) |

## Структура

```
lib/
  config.ts            настройки: подключение к провайдеру (env + ввод из UI), пути к данным
  db.ts                SQLite: сессии, сообщения, сценарии, оценки, кэш-ключи
  ai/                  AiProvider: интерфейс, OpenAI-совместимая реализация,
                       строгий JSON, ошибки (AiError)
  scenarios/           оси (axes), генератор сцены (generate), «актёр»-пациент (actor)
  personas.ts          персонажи: портрет + психология + голос (единый источник)
  speech.ts            озвучка с дисковым кэшем (sha256)
  evaluation/          рубрика, калибровка, оценщик (evaluator)
  session/service.ts   сервис сессий: сцена → диалог → оценка → история
  types.ts             общие типы (DTO)
components/
  avatar/              SVG-риг лица, виземы, эмоции, аниматор (AvatarRig)
  home/  session/      экраны выбора, сцены (запись голоса, караоке, супервизор)
  results/  history/   разбор и история
  settings/            экран и модальное окно «Подключение» (ключ, адрес провайдера)
app/api/               REST: sessions, turn, evaluate, stt, audio, history, settings
scripts/               probe, e2e-smoke, eval-regression, regression-cases,
                       open-when-ready (открыть браузер), get-node.ps1 (скачать портативный Node)
start.cmd              запуск на Windows двойным кликом: Node → зависимости → сервер → браузер
.node/                 портативный Node.js, скачанный start.cmd (в .gitignore)
EVALUATION_STANDARDS.md  критерии: стандарт → шкала → как проверяется
```

Ключевые внутренние контракты:

- **Сцена**. `startSession` собирает оси (домен/категория → эмоция → персона →
  мотив), генератор возвращает открывающую реплику и «актёрские заметки».
  Антиповтор: последние комбинации и сводка уходят в промт генератора.
- **Диалог**. Каждый ответ врача сохраняется; если лимит обменов достигнут —
  сессия переходит в статус `evaluating`, иначе `producePatientLine` возвращает
  реплику пациента с эмоцией; она синтезируется и отдаётся как mp3.
- **Оценка**. `evaluateDialogue` получает категорию, портрет пациента, скрытый
  мотив, полную транскрипцию, рубрику и калибровку; отвечает строгим JSON.
- **Безопасность**. `safety_flag` отделён от баллов; prompt injection в ответе
  игнорируется и фиксируется во `flags` (проверяется регресс-набором).

## Примечания

- Всё аудио и картинки генерируются локально-серверно; в браузере нет ключей.
- Кэш озвучки хранится в `DATA_DIR/tts` и переживает перезапуски; файлы
  отдаются как неизменяемые `/api/audio/<hash>.mp3`.
- Ключ провайдера попадает в интерфейс только маской. Хранится он либо в
  `data/settings.json` (ввод через экран «Подключение»), либо в `.env`.
  `.env`, `data/`, `.node/` и артефакты сборки в `.gitignore` — в репозиторий ключ не попадает.
- `start.cmd` качает Node.js версии `v22.23.1`; чтобы поднять версию, поменяйте
  `$Version` в начале `scripts/get-node.ps1`.
- Требование к микрофону: браузер с поддержкой `MediaRecorder`
  (Chrome/Edge — webm/opus; Safari — mp4). Запись с не HTTPS-хоста работает
  только на `localhost`.
