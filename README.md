# Vera Practice

Тренажёр клинической коммуникации для студентов-медиков и ординаторов.
Студент разговаривает с симулированным собеседником — голосом или текстом —
и получает разбор по признанным стандартам: NURSE, Calgary–Cambridge,
SPIKES, CANDOR и принципам Beauchamp & Childress.

Собеседник не идёт по заранее написанному дереву: он реагирует на конкретные
формулировки студента и рассказывает о себе только то, о чём его спросили.

---

## Что внутри

**Девять разделов практики, 64 кейса**

| Раздел | Кейсов | Формат | Стандарт |
|---|---|---|---|
| Конфликт с пациентом | 7 | короткая сцена | NURSE + Calgary–Cambridge |
| Медицинский колл-центр | 12 | только голос | Telephone triage + service recovery |
| Полный приём: регистратура → выписка | 7 | длинная консультация | Calgary–Cambridge |
| Сообщение тяжёлых новостей | 6 | короткая сцена | SPIKES |
| Согласие и этика | 6 | короткая сцена | Informed consent + Four Principles |
| Мотивационная беседа | 7 | короткая сцена | OARS + Motivational Interviewing |
| Раскрытие врачебной ошибки | 6 | короткая сцена | Open disclosure / CANDOR |
| Разговор с семьёй | 6 | короткая сцена | Family systems + shared decision-making |
| Барьеры коммуникации | 7 | короткая сцена | Health literacy + accessible communication |

**Скрытая карточка кейса.** У колл-центра и полного приёма собеседник держит
полный набор фактов — жалобы, анамнез, лекарства, аллергии, страхи, скрытые
обстоятельства. Он отвечает правдиво, но только на заданный вопрос. Что
студент спросил, а что пропустил, считает движок по ключевым словам вопроса,
а не модель: это бесплатно, воспроизводимо и не зависит от настроения LLM.

**Два режима.** Практика — сколько угодно попыток и развёрнутый разбор.
Экзамен — один заход на кейс, 30 минут, набор кейсов назначает преподаватель,
переиграть нельзя, результат уходит в журнал.

**Прогресс студента.** Динамика результата по времени, разбор по критериям с
трендом, карта расспроса «что спрашиваю — что пропускаю», выгрузка в CSV, JSON
и печать отчёта в PDF.

**Кабинет преподавателя.** Ростер, лимиты и отключение доступа, назначение
экзаменов, агрегаты «где группа проседает», транскрипт любой сессии, выгрузка
журнала в CSV.

## Запуск

**Windows: двойной клик по `start.cmd`.** Скрипт сам проверит Node.js (при
необходимости скачает портативную сборку в `.node`), поставит зависимости,
соберёт приложение и поднимет сервер. Права администратора не нужны.

Первый запуск занимает пару минут — идут установка зависимостей и сборка.
Дальше запуск мгновенный: собранная версия переиспользуется.

Консольное окно закрывать нельзя: пока оно открыто, тренажёр работает.

**После обновления кода запустите `rebuild.cmd`** — `start.cmd` поднимает уже
собранную версию и сам её не пересобирает.

### Ключ AI-провайдера

Ключа **нет ни в репозитории, ни в архиве проекта**. При первом запуске
`start.cmd` сам попросит вставить ключ в консоль (ввод скрыт звёздочками),
проверит его у провайдера и сохранит на этом компьютере. Дальше запуски идут
без вопросов: консоль лишь показывает маску вида `sk-…abcd`.

- Ключ хранится в `data/settings.json` **зашифрованным под учётную запись
  Windows** (DPAPI — тем же механизмом Windows хранит сохранённые пароли).
  Скопированная папка или архив на другом компьютере ключа не раскрывают:
  там `start.cmd` просто попросит ключ заново.
- Заменить ключ: `npm run setup:key -- --change` или кабинет преподавателя →
  «Подключение AI». Пропустили ввод при установке — введите там же.
- Для разработки ключ можно держать в `.env` (`AI_API_KEY=…`, образец —
  `.env.example`): все `.env*`, кроме шаблона, и папка `data/` — в `.gitignore`.
- Архив для сдачи без ключа и без базы: `npm run pack:handin` →
  `handin/vera-practice-<дата>.zip`.

Честная граница: программа, запущенная под той же учётной записью Windows,
ключ расшифровать может — иначе не смог бы и сам тренажёр. Поэтому для кафедры
лучше выпустить **отдельный ключ с небольшим балансом**: если он утечёт, его
отзывают у провайдера, не трогая ваш. Удаление файла ключ не спасает — только отзыв.

Страховка от случайной публикации в git:

```bash
npm run check:secrets                          # файлы, которые уйдут в git
node scripts/check-secrets.mjs --history       # плюс вся история — перед первым push
git config core.hooksPath .githooks            # один раз: проверка перед каждым коммитом
```

Загружать проект на GitHub через веб-кнопку «Upload files» нельзя: она не
смотрит на `.gitignore` и выложит `.env` вместе с остальным.

### Первый запуск

Пока в базе нет ни одного преподавателя, сервер печатает в консоль **код
запуска**:

```
  ПЕРВЫЙ ЗАПУСК: аккаунта преподавателя ещё нет.
  Откройте приложение, нажмите «Первый запуск преподавателя»
  и введите этот код запуска:

        KSGJY2TBEW
```

Код виден только тому, кто сидит за сервером, и гаснет после создания первого
аккаунта. Он перевыпускается на каждом старте, так что перезапуск сервера не
проблема. Альтернатива — задать `ADMIN_PASSWORD` в `.env`.

Дальше преподаватель заходит в свой кабинет, создаёт группу и аккаунты
студентов. Студенты ничего не настраивают и никаких ключей не вставляют.

### Работа с других компьютеров кафедры

Сервер поднимается на одной машине, остальные открывают его по сети:
`http://<ip-сервера>:3000`. Специально для этого сценария:

- флаг `Secure` на cookie входа ставится по фактическому протоколу запроса,
  а не по режиму сборки — иначе по HTTP в локальной сети вход был бы невозможен;
- проверка межсайтовых запросов сверяется с заголовком `Host`, а не с
  внутренним адресом Next;
- лимит попыток входа по адресу мягкий: студенты сидят за общими машинами и
  за одним NAT, и опечатка соседа не должна блокировать группу;
- `GET /api/health` показывает, что сервис поднялся и ключ провайдера задан.

Если сервис стоит за HTTPS — поставьте `FORCE_SECURE_COOKIE=1`.

**Голосовой ответ по сети требует HTTPS.** Браузеры дают доступ к микрофону
только на HTTPS или на `localhost`. На самом сервере голос работает, а с
других компьютеров по `http://<ip-сервера>:3000` кнопка «Голосом» недоступна —
тренажёр прямо об этом пишет, и студенты отвечают текстом. Озвучка пациента,
разбор и всё остальное работают и по HTTP. Чтобы включить голос по сети,
поставьте перед сервером обратный прокси с HTTPS (например, Caddy) и задайте
`FORCE_SECURE_COOKIE=1`.

### Ощущение приложения

Кнопка в шапке разворачивает тренажёр на весь экран (Fullscreen API), выбор
запоминается и восстанавливается при следующем заходе. Это основной способ:
на общих компьютерах ставить PWA не всегда уместно. Манифест и service worker
есть — «добавить на главный экран» работает как дополнительная возможность.

## Модели и стоимость

| Роль | Модель | Почему |
|---|---|---|
| Синтез диалога: сценарист и «живой» собеседник | `qwen/qwen3-next-80b-a3b-instruct` | держит роль, не скатывается в канцелярит, дёшев на объёме |
| Разбор и анализ | `minimax/minimax-01` | длинный контекст под полную транскрипцию с карточкой кейса |
| Озвучка | `openai/gpt-4o-mini-tts` | у остальных TTS нет |
| Распознавание речи | `openai/gpt-4o-mini-transcribe` | — |

Ключ провайдера живёт **только на компьютере, где запущен тренажёр** —
зашифрованным в `data/settings.json` (см. «Ключ AI-провайдера» выше). В браузер
он не попадает: к провайдеру обращается сам тренажёр, наружу отдаётся лишь
маска вида `sk-…abcd`.

**Что удерживает расход:**

- озвучка кэшируется на диск по хэшу текста, голоса и эмоции — одна и та же
  реплика синтезируется один раз;
- каждое платное обращение списывается из лимита студента: генерация сцены,
  реплика собеседника, распознавание речи, разбор. Лимит по умолчанию —
  `DEFAULT_REQUEST_QUOTA` (200), преподаватель меняет его поштучно;
- последний ответ врача собеседнику не отправляется (он только запускает
  разбор) и лимит не тратит; ход, на который собеседник не смог ответить
  из-за сбоя провайдера, откатывается и повторяется;
- покрытие расспроса, прогресс и все агрегаты считаются из базы, без модели;
- отключить одного студента можно, не трогая остальных.

Ориентир: короткая сцена ≈ 7 единиц лимита (1 генерация + 2 реплики +
до 3 распознаваний + 1 разбор), полный приём ≈ 25.

## Проверки

```bash
npm run typecheck        # строгий TypeScript
npm run check:coverage   # матчер покрытия расспроса, без сети и денег
npm run check:secrets    # в git не уходит ключ, .env и база
npm run smoke:backend    # проверки бэкенда: доступ, права, лимиты, CSRF, формат ошибок, выгрузки
npm run regression       # регресс AI-оценщика на калибровочном наборе (платный)
npm run seed             # демо-история для показа экранов, без обращений к AI
npm run setup:key        # ввести или заменить ключ AI-провайдера (-- --change)
npm run pack:handin      # архив проекта для сдачи: без ключа и без базы
```

Смоук бэкенда создаёт аккаунты, поэтому поднимайте под него отдельную базу:

```bash
DATA_DIR=data-smoke npx next start -p 3100
BASE_URL=http://127.0.0.1:3100 ADMIN_PASSWORD=<код из консоли> npm run smoke:backend
```

Регресс обязателен при любом изменении промта оценщика или модели — см.
[EVALUATION_STANDARDS.md](EVALUATION_STANDARDS.md).

## Стек и архитектура

- Next.js 15 (App Router) + React 19 + TypeScript strict, один сервер
- SQLite через better-sqlite3 (WAL); кэш озвучки и настройки — на диске
- Анимация лица — прямые DOM-мутации в rAF, без ре-рендеров React на кадр
- Графики — собственный SVG, без графических библиотек

```
app/api/          HTTP API — единственная точка связи интерфейса с сервером
components/       интерфейс (клиентские компоненты по экранам)
docs/API.md       контракты API: маршруты, тела, ответы, коды ошибок
lib/
  domains/        реестр разделов: по файлу на раздел + движок покрытия;
                  catalog.ts — публичная проекция для браузера
  scenarios/      генератор сцены и «актёр»-собеседник
  evaluation/     рубрики, калибровки, оценщик
  session/        жизненный цикл сцены и DTO разбора
  progress.ts     история прогресса и выгрузки
  auth.ts         вход, роли, защита запросов
  errors.ts       единый формат ошибок API и тексты кодов
  accounts.ts     группы, студенты, лимиты, задания
  db.ts           схема, миграции, агрегаты
  types.ts        общие типы и DTO сервера и клиента
```

Интерфейс можно переписать целиком, не трогая `lib/` и `app/api/`: всё, что
ему нужно, описано в [docs/API.md](docs/API.md), а типы ответов лежат в
`lib/types.ts`. Главное правило — клиентский код не импортирует реестр доменов,
базу и конфиг: иначе скрытые карточки кейсов попадут в браузер.

Добавить раздел = новый файл в `lib/domains/` и строка в реестре. Ядро при
этом не меняется: домен для движка — параметр, у него своя схема карточки
кейса и свой применимый стандарт оценки.

Node.js ≥ 20. Проверено на Node 22, Windows 10/11.

## Данные и приватность

- Всё хранится локально в `data/`: база, кэш озвучки и зашифрованный ключ провайдера.
- Наружу уходят только обращения к AI-провайдеру: текст реплик для синтеза
  ответа, текст для озвучки и аудио для распознавания.
- Service worker кэширует только статические файлы. Ответы API, сессии и
  аудио не кэшируются никогда.
- Пароли хранятся в виде scrypt-хэшей. Отключение студента и смена пароля
  немедленно гасят все его активные входы.
